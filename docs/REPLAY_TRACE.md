# Deterministic Replay and Bounded Trace

Status: experimental P2-05 library profile. This contract owns user replay, observational diagnostics and first-observed divergence reports. [Checkpoint/restore](CHECKPOINT_RESTORE.md) owns strict persisted command format, integrity, compatibility, provider permits, reconstruction and output cursors. [Event execution](EVENT_EXECUTION.md), [workflow](WORKFLOW_EXECUTION.md) and [temporal scheduler](TEMPORAL_SCHEDULER.md) retain computational authority. Replay/trace does not add a second financial evaluator or complete the P2 temporal gate.

## Observation without computation changes

`TraceBuffer::off()` is the default. `TraceBuffer::new(TraceLimits)` enables an owned bounded collector:1..4096 entries and1..4194304 charged bytes. Runtime trace collection performs no IO, callbacks into application code, provider evaluation, scheduling or numerical operations. It copies values already computed by the existing evaluator. Provider calls retain their ordinary run/event/call sequences; crossing subscriptions still advance once per accepted event. The lower-level IR `evaluate_observed` passes borrowed computed call/crossing observations to a trusted observer; applications supplying their own observer must not panic or cause provider/external side effects. The runtime uses only its internal collector, not a user callback.

The trace is a captured prefix. The first entry/count/byte overflow permanently seals that collector; later record attempts increment a saturating dropped count and do not build entries. Strategy execution continues normally. No trace overflow can become a numeric/strategy error, advance or roll back a cursor, change a signal, alter provider calls, or exhaust the checkpoint command quota early. `used_bytes`, `entries`, `dropped`, `truncated` and configured limits are separately inspectable. Charged bytes are the exact same-engine Debug UTF-8 length of retained typed TraceRecord DTOs, counted by a bounded formatting writer without creating an intermediate complete string. This bounds retained diagnostic storage/format length, not allocator overhead, transient copies, CPU latency, provider execution or OS resources.

No diagnostic fields enter EventObservation, WorkflowObservation, CommandReceipt semantic results, manifests or checkpoint outcome hashes. Trace on/off/exhausted runs produce identical semantic receipts and checkpoint bytes under the same engine. Private reconstruction defaults to trace off; it does not silently recollect or append historical diagnostics to a caller's collector. A caller can keep its prefix collector and append only restored continuation events.

## Trace data and provenance

`events::EventRuntime::step_traced`, `workflow::WorkflowRuntime::step_traced`, `instances::InstanceScheduler::drive_one_traced` and `checkpoint::CheckpointRuntime::execute_traced` use the existing execution paths. Every retained TraceEntry carries run, execution identity, optional logical event sequence/timestamp, scoped node vector, original enclosing source definition/call sites and an optional logical evaluator subpath. Under the coordinator, sequence is the globally assigned logical sequence; source-delivery records additionally carry stream, dataset identity, original source sequence and the published alignment frontier `(source_sequence,logical_sequence,timestamp_ns)` per stream. It never exposes queued future records.

| Phase / data | Observed boundary |
| --- | --- |
| source-delivery | Exact queued lane delivery/provenance before computation |
| provider-candidate | Existing incremental graph node outputs, with compiled node path and source map |
| pure-call-candidate | Actually invoked pure provider ID/call ordinal/output map at its enclosing expression source; lazy skipped calls are absent |
| crossing-candidate | Already computed previous/current typed operand pair and ready/missing/warmup crossing output |
| event-roots-candidate | Computed event public outputs |
| workflow-inputs/guard/effects/outputs-candidate | Old state/Delay/mode/input slots, evaluated guards, selected writes and public outputs |
| workflow-state-candidate | Typed old/new cells, mode and Delay; includes module/state-schema identities |
| windows-candidate | Old/new active windows and expiry notices from the joint staged transaction |
| timer-before / timer-committed | Existing event-time timer book and actual expiry notice |
| lane-rejected | Original structured error/source path; staged provider/workflow changes were discarded |
| command-result | One-based journal index, produced-output sequence and accepted/command-rejected/lane-rejected outcome |

Candidate records describe attempted computation, **not committed state**. A later workflow/temporal failure can discard all earlier candidate values. Consult the operation result and final command marker; truncation can omit that marker, so an incomplete diagnostic prefix must never prove commit. Standalone traced step callers must consult the returned Result; the outer checkpoint command marker exists only in execute_traced. A lane rejection can itself be an accepted coordinator dispatch receipt while its computational event remains unchanged and quarantined.

Pure expression lowering retains an enclosing expression/source and deterministic call ordinal; it does not reconstruct a source map for every inlined original pure graph node or every recursive Boolean/arithmetic AST child. No skipped branch is evaluated to improve diagnostics. Provider buffers remain opaque; traces observe declared outputs and host-owned state, not private implementation memory. Timer records have event time but no invented source event sequence. These limits are explicit; node/event provenance must not be relabeled as hidden-cause proof.

## User replay and references

`replay::replay(seed, checkpoint_bytes, optional_trace_limits, optional_reference)` strictly parses/checks checkpoint integrity/quotas, expected complete seed pins/provider permits and reference configuration **before creating provider state**. It builds a separate candidate and executes the saved bounded command prefix through the same wrapper, comparing every outcome digest and produced-output cursor. No historical CommandReceipt or external signal-publisher callback is returned. A verified result provides the resumed runtime, trace, verified command count and whether reference comparison covered a complete trace. Future execution continues after the saved cursor. Client acknowledgements/outbox/exactly-once delivery remain outside this API.

`TraceReference::capture(runtime,collector)` freezes a trusted in-memory diagnostic baseline with pins, command count, limits, typed entries and truncation status. Supply the collector used for the same whole run prefix; standalone unscoped observations, nonmonotone/gapped command scopes or an untruncated incomplete prefix fail capture. Matching pins/count/limits are required on replay. A reference can intentionally represent an alternative input history of the same shape to locate its first observed difference. This is host-provided evidence, not a signed/authenticated log or a stable persisted cross-language format. Native Rust DTO Debug presentation is not a wire ABI; future Desktop/worker transport needs its own versioned mapping.

`ReplayOutcome::Verified` means every saved command outcome/cursor matched. Without a reference it makes no trace-equality claim. `complete_trace_comparison=true` additionally requires enabled, untruncated, exactly equal reference and actual entries. A matching bounded prefix or trace-off baseline leaves that flag false; it cannot prove unseen nodes equal. Truncation never skips full command outcome verification.

`ReplayOutcome::Diverged` drops the reconstruction candidate and reports one-based command index, expected/actual outcome IDs/cursors and bounded collected evidence. With an actual observed trace mismatch it includes expected/actual typed records and the first mismatching context (run/event/node/source/expression). A digest/cursor mismatch without differing recorded evidence reports CommandOutcome with **no guessed node location**. If tracing stopped earlier, a later outcome mismatch remains detectable but may only be localized to its command. A trace mismatch can occur even when public outcome digests match; it is separately labeled ObservedTrace. Structural/integrity/compatibility/configuration errors remain Err, not a valid divergent replay. Failure never mutates an existing live run.

The checkpoint1024-command/262144-byte limits, deterministic side-effect-free provider requirements, same-engine implementation/outcome encoding and reconstruction cost apply unchanged. This is bounded synchronous local replay, not a streaming historian, arbitrary legacy IO rollback, native provider codec, worker sandbox or debugger UI.

## Executable evidence

[Replay/trace tests](../crates/fqe-runtime/tests/replay_trace.rs) compare all receipts and final checkpoint bytes with tracing off/full/entry-exhausted/byte-exhausted; repeat actual MACD/RSI/crossing/window/state traces; split continuation at every command without recollecting history; preserve temporal failure rollback and independent lanes; reject bad configuration/references; and intentionally alter input to locate logical event3/source outputs. Wrong saved outcomes without source evidence stay command-only. [Expression tests](../crates/fqe-ir/tests/expression_contract.rs) use a counted independent provider to verify borrowed observations add no calls and preserve crossing/output results. [Pure event fixture](../crates/fqe-runtime/tests/fixtures/p2/trace-pure-event.json) verifies existing registered pure evaluation and enclosing-source/call-ordinal tracing; older goldens remain unchanged.

`cargo run --locked --offline -p fqe-runtime --example replay` creates/replays the existing local synthetic workflow and compares a second full trace. An explicit checkpoint path reads the exact seed used by the checkpoint example: run `--example checkpoint -- /tmp/fqe-example.checkpoint.json`, then `--example replay -- /tmp/fqe-example.checkpoint.json`. This is a runnable library demonstration, not a general CLI/Flutter import flow. No Python/runtime download/login/trading account is required for the engine examples.

Full verification/evidence commit is recorded in [Project status](PROJECT_STATUS.md); focused tests alone do not close the task. P2-06 owns the full MACD-cross → wait3 → RSI/G-006 and X-002 temporal gate. P3 backtesting/simulation, P4 actual Desk/Flutter packaging and P5/P6 external languages/plugins remain downstream. No new dependency/lockfile/toolchain or protected financial implementation changes are needed.
