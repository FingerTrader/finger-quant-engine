# Experimental desktop boundary v1

P4-01 selects a **bundled private stdio engine process**, implemented in the first-party `fqe-bridge` crate / `fqe-desktop-peer` executable. FFI is a runnable comparison candidate. This is a versioned experimental local client boundary, not a published production compatibility guarantee. [ADR-034](ARCHITECTURE_DECISIONS.md#adr-034--bundled-private-stdio-desktop-boundary) records evidence and selection. [Managed controls](ENGINE_CONTROLS.md) extend this boundary in P4-02; actual Desk UI/durable persistence remains P4-03/P4-05; external language execution remains P5/P6.

## Scope and authority

Rust performs actual loaded Event/Workflow compilation, historical selection, policies, simulation and balanced ledger/report calculation. The client receives the native complete report; it cannot replace missing financial fields with a Dart backtester. Core P3 source/fixture pins remain unchanged. The workspace manifest/lock change legitimately changes the native engine identity; no old checkpoint migration is implied. `bridge_id` fingerprints bridge source/manifest only; the full native engine identity is pinned separately in each financial manifest. Package version alone is not source identity.

No Flutter, login, account onboarding, Trading SDK, broker secret, filesystem path, runtime download, compiler or network endpoint is a request prerequisite. `account.id` identifies a virtual local account. Only the reviewed in-process reference catalog is available; descriptor listing does not load external code. Module parameters remain those declared in the artifact, while top-level bindings are explicit typed inputs.

## Framing and versioning

A host starts one explicit absolute bundled executable with `Process.start`, no shell, no inherited credential environment, private stdin/stdout pipes and bounded stderr. There is no shared daemon, port or discoverable endpoint. Possession of the private pipe is the local access boundary; it is not a hostile same-user isolation or cryptographic authentication claim. App Sandbox helper inherits the app's restrictions. The host supplies selected file bytes, so the helper needs no independent path grant.

Each frame is four unsigned big-endian length bytes followed by exactly that many UTF-8 JSON bytes. Input length1..262144, whole output envelope1..4194304; reject length before allocating the body. Native reports have their own4MiB ceiling; if report plus envelope exceeds the whole-message ceiling return `response_quota`, never truncate a success. This tightens the initial planning shorthand “4MiB+envelope” to one bounded4MiB message. Depth32,32768 input JSON items,4096 items per collection,128-byte keys, all constrained by the same total byte budget. Model/CSV strings may exceed4KB; the dedicated outer codec preserves the stricter unchanged core model decoder. Duplicate keys, invalid UTF-8, trailing documents, floats, signed numeric literals and integer literals aboveu32 are rejected. Financial decimals, quantity, money, timestamps, seeds and counters are canonical strings; schema and protocol version fields are small unsigned JSON integers.

Request has exactly `format:"fqe.desktop-request"`, `schema_version:1`, `id`, `method`, `params`. ID1..64 ASCII letters/digits/`._-`; method<=64bytes; params object. Methods reject unknown/missing fields except arbitrary bounded `echo` params. Response has exactly `format:"fqe.desktop-response"`, `schema_version:1`, `id`, `ok`, `body`. A parse failure has null ID; a valid request gets its exact ID. Success body is method-specific; error body has stable `code`/`path`, no source/token/credential echo. Malformed/unknown/duplicate reply IDs disconnect the provided Dart pipe client. Error diagnostics do not establish hostile-code isolation. Duplicate request execution/retry deduplication is not delivered by P4-01; do not automatically retry an uncertain run.

`hello` params: unsigned integer `major`, `minor`, and required capability string array<=32. Only major1 supported; negotiate minor0 against any nonnegativeu32 client minor. Unknown required capabilities fail. Hello includes actual selected versions, supported capability list, bridge source ID, package version, request/result/bar limits, `financial_authority:"native-ledger"` and experimental maturity. The stub explicitly verifies these fields/capabilities before its measured journey. Required-field/type/semantic changes need a new major or negotiated required capability; unknown mandatory features never silently fall back. The old `.proto` and version-number helper remain draft/separate, with no generated financial codec claim. A client boundary does not make Dart or another caller a strategy runtime.

## Methods and ownership

| Method | Exact params | Behavior |
| --- | --- | --- |
| `hello` | `major`, `minor`, `required` | Compatibility/capability presence and limits |
| `echo` | Any bounded object | Exact transport measurement only |
| `model.validate` | `kind`, `model`, `parameters` | `kind` event/workflow, UTF-8 model JSON text and version1 typed binding JSON text; native compile/actual bound parameters/execution/registry IDs |
| `descriptor.list` | Same model params | Full versioned reference-catalog descriptor objects: names/typed ports/parameters/readiness/semantics/metadata/pins; no per-indicator dispatch |
| `backtest.run` | Fields below | Frozen native financial batch; full report/manifest/result IDs |
| `cancel` | `request_id` | Pipe-only cancellation delivery acknowledgement for the current financial worker; terminal report remains authoritative |

Backtest requires `kind`, `model`, `parameters`, `history_spec`, `csv`, `start_ns`, `end_ns`, `warmup_bars`, `run`, `seed`, `account`, `policies`. Model/spec/CSV are text bytes, not paths; range/time/seed/warmup are exact unsigned strings. Immutable dataset/spec/native history rules and256-source-bar limit remain P3's. Current revision import has no parent-dataset input; unsupported parented revisions fail explicitly rather than being stripped.

`account` requires `id`, `profile`, `initial_cash`, `participation_bps`, `fee_bps`, `minimum_fee`, `slippage_bps`, `risk`. Profiles `cash_long` with null risk or `margin_long` with exact `max_leverage_bps`/`maintenance_bps` string fields. Native units/scales/steps/cost/risk preflight apply. Policies<=16 each have `id`, `source`, `action`; sources `long_signal`, `event_boolean`+`name`, `workflow_boolean`+`instance`+`output`; actions `buy_if_flat`+exact `quantity`/`cash_cap` or `close_long`. Unknown ports/profiles/fields reject before execution. No implicit Long→order policy or trading-account mapping.

The peer permits one financial worker, while the reader handles cancellation/short methods. Another overlapping financial request returns `busy` unless the previous worker has already finished. Cancel `accepted` means the flag was delivered, not a guarantee it won a completion race. Actual `completed`/`cancelled` report is authoritative. Cancellation checks between source bars; native preparation and a provider invocation are not forcibly interrupted. EOF sets cancellation, joins the worker and exits. The provided host stub has a5-second request deadline, kills a disconnected/overdue peer and fails pending requests; teardown completes within the measured2-second budget. No hidden auto-resume/backend switch. [Managed controls](ENGINE_CONTROLS.md) add application-owned in-memory jobs/lifecycle cursors/normal graceful EOF in P4-02; durable files/actual app shutdown/reopen remain P4-03.

## Runnable candidates and native feasibility

`examples/desktop/client.dart` uses only Dart SDK libraries. It runs with actual Desk app pin3.5.1/Flutter3.24.1 without `pub get`, plugin builds or a customer-installed Rust runtime. `PipeClient` bounds16 pending calls/4MiB frame/64KiB stderr count (does not retain log content), validates version/correlation and fails on disconnect/timeout. `FfiClient` runs native calls off-main in an isolate and demonstrates native-owned bounded buffers/task cancellation, with no Dart FFI package or generated binding. FFI's isolated crate permits only export attributes; engine crates retain unsafe forbid. Trusted host pointer access is not sandboxing; a fatal native fault or uncooperative call can take down/block its Dart host. FFI remains a comparison candidate, not the selected product transport.

Build with the pinned toolchain: `cargo build --release -p fqe-bridge --locked --offline`. Run `dart --disable-dart-dev examples/desktop/compare.dart ROOT ARTIFACT_DIRECTORY OUTPUT_DIRECTORY` with Desk's verified SDK binary. The measurement script verifies exactu64/decimal/null presence,100 echoes, version/capability rejection, descriptor discovery, actual7-bar financial report parity, host timer, early bar-safe cancellation, zero FFI buffers/tasks and killed-peer cleanup. It preserves rejected candidate budgets; the selected IPC must pass. Then run `python3 scripts/check_desktop_peer.py --peer target/release/fqe-desktop-peer --request OUTPUT_DIRECTORY/request.json` and the independent P3 portfolio oracle against `ipc-report.json`.

`examples/desktop/client_failures.dart FAULT_FIXTURE_DIRECTORY` uses the first-party C fixture `macos/fault_peer.c` to prove oversized/truncated/invalid/unknown-ID/duplicate replies, stderr flooding and request timeout cleanup. Compile that fixture with existing system clang, then create mode-named symlinks as recorded in the acceptance report. This fixture is never a product worker.

`python3 scripts/check_desktop_bundle.py --artifacts target/release --request OUTPUT_DIRECTORY/request.json --output NEW_TMP_DIRECTORY` compiles a disposable first-party native `.app`, embeds both candidates/resources, fixes candidate dylib install ID, ad-hoc signs each nested artifact then parent, verifies signatures/native dependencies and runs actual complete financial requests in App Sandbox. Host release entitlements match Desk's sandbox/user-selected-read-only/network-client keys; helper has exactly sandbox+inherit per [Apple helper guidance](https://developer.apple.com/documentation/xcode/embedding-a-helper-tool-in-a-sandboxed-app). Probe verifies an ungranted public source file outside the bundle is denied. Native candidate dependencies are only system libSystem; no dev checkout/compiler/interpreter is needed by the bundled worker. Managed nested sandbox initialization can abort before main; run the **temporary probe only** under the appropriate execution permission rather than disabling sandbox entitlements. This is real native packaging feasibility, not actual Desk UI, Developer-ID/Store signing, installation, clean-machine or all-platform acceptance.
