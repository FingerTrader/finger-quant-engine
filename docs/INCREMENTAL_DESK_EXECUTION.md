# Incremental Desk execution

Implemented experimental extension `run.incremental/1` within P4-03.03; it does not close the wider phase. Existing `run.start`, lifecycle events, immutable reports and optimization remain compatible. Strategy/order/ledger code is reused.

- `run.start_live {session_id, operation_id, input}` admits a research task with its own operation fingerprint domain. Unsupported kinds reject explicitly; no silent batch fallback. The worker starts gated before the first main close.
- `run.advance {session_id, handle, after}` grants exactly the next main-bar prefix. Repeating a grant while it is outstanding does not add credit. `after` must equal the committed cursor. Grants never run strategy code in the request thread.
- `run.live {session_id, handle, after}` reads the last committed snapshot without granting work. `after` must be the current or immediately preceding cursor. Snapshot is null when caught up; future/expired cursors reject. Replies bind session/handle/cursor/terminal. All counters are canonical unsigned strings.
- Each snapshot contains processed/total, native close/source sequence, account and marks, current equity/cash/fees/realized/unrealized P&L, and only newly committed fills/order events/decisions. One snapshot is retained, bounded by the existing graph/order/request/response quotas. The next grant acknowledges the old frame. Consumers must consume a frame before advancing; stdout remains framed request/response, with no unsolicited output.
- The existing research loop computes the frame after main-close decisions/account valuation. Before the following incoming-open matching it waits for the next grant; pause therefore cannot invisibly fill the next bar. Secondary markets and periods retain existing deterministic ordering.
- Desk owns the pacing (1/2/5/10/20x), stopping grants on pause, granting one on step and polling the outstanding grant. One already granted bar may commit before pause settles. A stopped run sets cancellation before clearing its prefix; worker gates check cancellation every2ms. EOF/shutdown also cancels and joins.
- Stop discards transient UI/cache data and does not retrieve/restore a partial financial report. A cancelled metadata/input record remains for diagnostics; saved source data, strategy and previous completed reports are preserved. A later Play uses a new operation, no restored strategy/ledger state. Late prior frames are ignored.
- On normal completion, canonical full report verification/persistence remains independent. Desk retains the last displayed frame during archival and does not replay the same execution a second time. Explicit saved-history selection continues the existing read-only animation.
