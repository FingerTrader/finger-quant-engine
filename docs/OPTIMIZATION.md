# Local parameter optimization

Implemented experimental P3-06 native Rust profile, `fqe_runtime::optimization::PreparedOptimization`; [Project status](PROJECT_STATUS.md) owns verification/closure. [Backtesting](BACKTESTING.md) owns each underlying financial run and its exact ledger/metrics. This contract owns finite parameter grids, scheduling, isolation, train/validation selection and aggregate research exports. No worker, distributed optimization, marketplace, live route, SDK/login, Flutter or data download is required.

## Request and conservative resource bounds

OptimizationRequest owns a loaded EventPlan or Workflow artifact, immutable provider registry, training/validation HistorySelections, explicit typed ParameterDimensions, policies/SimulationConfig, run ID, seed, SearchBudget and SearchControl. Dimensions target declared top-level event-graph parameters; fixed workflow-instance parameters remain pinned in the source artifact and every actual run manifest. Search does not edit IR, infer useful parameters, tune model/risk settings or replace unsupported names. A conforming declared parameter works without per-name engine branches.

At most8 uniquely named nonempty dimensions,16 exact values per dimension, and16 total Cartesian trials. Duplicate exact choices reject; dimensions sort by key, choice order stays explicit. Values retain exact types/scales/units; a type/unknown/constraint binding failure becomes that trial's diagnostic rather than corrupting other trials. Zero-dimensional search is rejected rather than mislabeled optimization. Run IDs<=64 identifier bytes leave space for generated native run IDs.

Training and validation each retain the256-source-bar limit, including warmup. Before any trial execution, require `trial_count × training_source_bars + validation_source_bars <= max_total_source_bars <=4096` and trial_count<=max_trials<=16. The reservation includes validation even when no trial succeeds or a cancellation later skips it. This bounds worst-case scheduled source bars, not elapsed CPU time. Existing model/broker/ledger limits remain in force; there is no retry loop. Search input manifest <=262144 bytes/shared strict decoder quotas; each backtest result <=4MiB; complete aggregate export <= configured max_report_bytes<=4MiB with exact JSON depth/item bounds. Exceeding the aggregate quota returns no aggregate result. These are experimental bounded research limits, not production memory/latency claims or a hostile-provider sandbox.

## Split discipline and independent state

Both selections must come from the exact same immutable dataset content ID, with continuous supported bars and matching financial metadata. Training's final close must be <= validation's performance start/open. Overlap or another revision/source snapshot is rejected. Validation warmup may contain earlier known training history; it must remain the selection's past-only warmup. All validation performance bars occur strictly after training bars under the close/open phase convention, even when their boundary nanosecond is equal. No validation performance value participates in compilation bindings, training prices, ranking or parameter selection.

Every trial compiles its actual typed bindings, creates a fresh Event/Workflow runtime, simulation broker, ledger, observations and report. Only immutable registry/artifact/history/configuration is shared. Capital, holdings, provider/crossing/module state, pending orders and fees never carry between trials. Selected-parameter validation is another fresh financial run with the configured initial cash; training's terminal position/P&L is not inherited. Past-only validation warmup is explicit historical context, not restored training state. The same trusted-provider factory/purity boundaries as Backtesting apply.

## Deterministic scheduling and identities

Canonical trial indices come from the Cartesian product over sorted dimension keys and explicit choice order. Trial parameter ID = SHA256 of `FQE-OPTIMIZATION-PARAMETERS/1` + newline + sorted compact JSON map of actual requested typed values. It excludes run/schedule, allowing a parameter set to be compared across seeds/data, while complete trial financial manifests carry those other identities.

Scheduling is sequential. Start `state=seed`; for descending Fisher-Yates i=count−1..1, add0x9e3779b97f4a7c15 modulo2^64, transform z by SplitMix64: `(z xor z>>30) × 0xbf58476d1ce4e5b9`, `(z xor z>>27) × 0x94d049bb133111eb`, `z xor z>>31`, with multiplication modulo2^64. Swap i with `z mod(i+1)`. Seed affects order only, with no stochastic price/fill model or cryptographic/uniformity promise. Different seeds can legitimately yield the same finite permutation. Actual order is recorded. Trial seed = request seed xor canonical index; run ID `<request>.t<index>`. Validation uses `<request>.validation` and the selected canonical index's trial seed.

Rank only Completed training runs: higher exact money net profit, then lower exact monetary max drawdown, then lexicographically smaller parameter-content-ID bytes. Identical baseline/config/currency/money scale make comparisons meaningful. Stable content-ID ties do not depend on finishing order, seed, validation results or arbitrary display labels. Cancelled/failed/not-run trials never enter ranking. Evaluate only the training winner on validation; publish its validation outcome separately, with no automatic reselection, combined equity curve or relabeling validation profit as training profit. A no-trade candidate may rank first; this is a measured outcome, not a strategy recommendation.

## Failure and cancellation

Each trial is NotRun, Failed(code/path/detail), Completed(full pinned BacktestResult), or Cancelled(committed explicit prefix). A compile/runtime/quota failure exposes no partial failed trial financial report and does not abort other trials. The overall scheduler can complete with failed trials or failed validation; inspect each outcome. If no completed training trial exists, terminal NoSuccessfulTrials has no selected parameter and validation NotRun.

SearchControl Complete runs normally. CancelAfterTrials(n),0<=n<=count, cancels before the next scheduled attempt and skips validation even when n=count. Count includes failed attempts. It records successful prefix trials and remaining NotRun. Shared AtomicBool is checked between trials, before validation and inside each backtest between bars; a cancelled partial training report is preserved as Cancelled and excluded from ranking. Cancellation may still carry truthful open positions/debt from already committed fills. There is no wall-clock timeout, interruption inside a provider, parallel scheduling, persisted optimizer resume or dynamic grid expansion in this profile.

## Exact aggregate provenance

`fqe.optimization-inputs`, schema_version1, pins source/canonical loaded artifact and registry, complete source-derived engine identity/version, run/seed, dataset/CSV/bars/spec source IDs and canonical spec, both selection IDs/ranges/warmup/source counts, complete account/model/cost/risk/limits/policies, typed grid/canonical requested trial maps, actual schedule, budget/control and versioned scheduling/seed/ranking/validation rules. Per-trial financial manifests separately freeze actual bound defaults, compiled execution IDs and full financial provenance. Unsuccessful bindings retain source/request/config pins and diagnostics.

Manifest ID = SHA256(`FQE-OPTIMIZATION-INPUTS/1` + newline + exact sorted manifest bytes). Aggregate result ID uses `FQE-OPTIMIZATION-RESULT/1` + newline + exact result bytes; IDs are returned natively rather than self-included. `fqe.optimization-result`, schema_version1, embeds manifest/ID, terminal/completed count, all canonical trial IDs/requested parameters/outcomes/full financial reports and report IDs, ranked training IDs, selected ID and separate validation outcome/report. Decimal/times/counts/seed are exact strings and schema/flags use integer/Boolean JSON. This is experimental export, without a stable external decoder/FFI ABI or persistence/migration promise.
