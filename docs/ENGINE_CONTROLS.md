## Process and state ownership

`fqe-bridge::managed::ManagedRuns` owns a process-session registry. `run.initialize {}` is idempotent and returns an opaque `session_id`, max_jobs4/max_operations64/max_active1 strings, `progress:"indeterminate-batch/1"`, `event_delivery:"pull-cursor/1"`. The private-pipe hello also carries this same session ID and managed capability; the existing optional capability negotiation rejects unsupported transports. Session identity derives from process ID and host start timestamp, not a secret/authentication or durable identity. Every later managed method requires the exact session ID, rejecting stale commands across restarts. No login/account permission or backend dependency.

Start is an asynchronous admission, not a financial success. Native states: `accepted` → `running` → `completed`/`cancelled`/`failed`; a delivered stop adds `cancelling` before an authoritative terminal. It may win before running or lose to completion; completed remains completed and can truthfully have stop_requested=true. Terminal outcomes are written once. A failed compile/preflight/execution has an explicit code/path, no financial result and no stale prior success. Same native `PreparedBacktest.run_with_cancel` owns all accounting and final/cancelled reports. Preparation/provider invocation is not hard-interruptible. There is one shared financial admission guard across managed jobs and legacy one-shot `backtest.run`; a concurrent new financial computation returns `busy`.

`run.start` requires `session_id`, `operation_id`, `input`. Input is the complete unchanged backtest params from the desktop boundary. Operation ID1..64 ASCII letters/digits/`._-`. Bind the exact canonical full request value (including model/data text, costs/risk/seed) to the operation with domain `FQE-DESKTOP-OPERATION/1`. Same operation/same input returns the same handle and duplicate=true without executing again; changed input returns `operation_conflict`. Formatting inside model/CSV text is part of the frozen request identity. Admission/worker creation failures do not consume an accepted operation. Handles `managed.N` are never reused in a process. Scope is this process session only; there is no distributed/durable exactly-once, auto-retry after death or live order permission.

At most4 retained jobs, including active/error/terminal results, and64 accepted operation receipts/tombstones; reject rather than evict. `run.release` only removes terminal jobs, clears financial storage and preserves the operation→handle/input tombstone. Repeated release succeeds. Repeating an old start after release returns the old handle/released=true, not a new run. New explicit operations need a free retained slot and available receipt budget. No hidden history cleanup can erase deduplication. A new process has a different session and no implicit restore/restart of old work.

EOF/shutdown closes admission, sets flags, joins owned workers and exits. The Dart transport now prefers graceful EOF when no RPC is pending; it allows1.5s for flush/exit then force-kills and waits up to0.5s. Pending/disconnected/overdue RPCs fail and force peer cleanup. A paused widget subscription cannot hold native teardown open. P4-03 defines durable app quit/reopen behavior; this registry is explicitly in-memory.

## Methods and exact reads

| Method | Params in addition to session_id | Behavior |
| --- | --- | --- |
| `run.start` | `operation_id`, `input` | Frozen admission, stable handle, duplicate/released flags |
| `run.status` | `handle` | Phase/terminal/stop flag/operation/high watermark; actual processed count/result ID/error when known |
| `run.stop` | `handle` | Idempotent flag delivery; never claims a terminal before native completion |
| `run.events` | `handle`, `after`, `limit` | Pull lifecycle records with exact contiguous cursor/high watermark/terminal; no unsolicited stdout frames |
| `run.result` | `handle` | Full authoritative report/manifest/result IDs; response envelope quota still applies |
| `run.result_chunk` | `handle`, `result_id`, `offset`, `max_bytes` | Exact immutable report bytes encoded lowercase hex; offset/next/total/eof, max_bytes1..65536 |
| `run.output` | `handle`, `result_id`, `section`, `after`, `limit` | Immutable report rows with cursor/total/eof; no extra strategy evaluation |
| `run.release` | `handle` | Terminal-only removal and retained deduplication tombstone |

All cursors/limits/counts/offsets are canonical unsigned strings. Limit1..16. Future/noncanonical cursor, unknown handle/section, wrong result ID, missing/extra fields and oversize pages reject; never silently skip. Chunk ranges are raw bytes, so a split cannot corrupt Unicode: decode hex/reassemble exact bytes before UTF-8/JSON parsing. Full report remains independently hashable and readable without execution. Chunk EOF at exact byte length is valid; no non-final zero-progress chunk. Every output page is bound to immutable result ID and process-session handle. Supported sections: observations, decisions, orders, fills, journal, execution_events, equity_curve. Result available only for native completed/cancelled outcomes; failed/pending/released are explicit errors. Native full report has4MiB ceiling; chunks let a client retrieve a valid full report even if an extra wrapper would exceed the whole-response ceiling.

Events are bounded lifecycle facts, at most4 per job: accepted, optional running/cancelling, terminal. `processed_source_bars` is null until native computation commits its report, then actual count. **No per-bar percentage/live fill stream is claimed.** This bounded native batch exposes indeterminate running progress and later exact historical observations/debug pages. Reads never rerun providers, reconstruct checkpoints to manufacture progress, rewrite a journal or trade. A current status can be newer than a previously fetched event page; consume cursor order before changing displayed phase. A repeated read returns the same committed rows, and a terminal read cannot change outcome.

`model.inspect` takes the same kind/model/parameters as validate, compiles natively and returns validated canonical artifact, full reviewed descriptors, actual top-level bound parameters and registry/execution IDs. Canonical Workflow modules/instances preserve their own typed parameter schemas/values. Ports/output/readiness/semantics/metadata are generic descriptor data; no per-indicator/rule-name branch. No external source/manifest discovery executes code or installs runtimes.
