# Bounded Checkpoint and Restore

Status: experimental P2-04 library profile, fqe.checkpoint/1. This contract owns complete **logical state reconstruction** through `bounded-deterministic-command-replay/1`, explicit provider capability, compatibility/integrity/output cursors and atomic local checkpoint publication. [Workflow](WORKFLOW_EXECUTION.md), [market scheduler](MARKET_SCHEDULER.md), [temporal scheduler](TEMPORAL_SCHEDULER.md) and their numeric/calendar/lifecycle contracts retain authority. It is a supported state representation with explicit quotas, not native provider-buffer serialization or a copied RunState/cell view.

## State representation and admission

`checkpoint::CheckpointRuntime` seeds an initially empty InstanceScheduler from immutable CheckpointSeed: schedule, host run, limits and lane IDs/runs/streams/compiled workflows/optional bound temporal rules. It records every supported typed ingress/control command and a digest of its deterministic owned outcome. Re-executing this exact command prefix with pinned deterministic implementations reconstructs all provider/indicator and crossing buffers, rule cells/Delay/modes, ingress cursors/watermarks, pending market queue/alignment, lane FIFOs/status/fairness, active windows/timers and produced-output cursor. Queued, rejected/blocked, retry/cancel and EOF boundaries are included. No Rust pointer, provider object, shared mutable buffer, pickle or implicit language serialization enters the file.

This profile intentionally stores the full bounded command history instead of a native state dump. It preserves the existing indicator implementation/artifact source pins and supplies complete reconstruction without introspecting opaque provider objects. Restore runs reviewed factories/computation again; it is suitable only for explicitly approved deterministic side-effect-free providers. It cannot safely replay arbitrary IO, randomness, global mutable state, credentials, live SDK calls or legacy already committed host operations. Those providers remain unsupported. Native codecs/compact long-run checkpoints and state migration require another negotiated representation; this task does not disguise replay cost as constant-time buffer loading.

Every registration defaults to checkpoint replay unsupported. Trusted host code must explicitly call `RegistryBuilder::permit_checkpoint_replay(key)` after reviewing an entry's deterministic factory/steps/outputs and absence of external effects. The frozen prepared calls carry this separate checkpoint permission. `catalog::reference` opts in its existing reviewed pure/indicator entries through generic descriptor iteration; no financial ID branch or source pin changes occur. This flag does not change existing numeric descriptor/registry/artifact canonical identities. A checkpointed seed checks every compiled provider node's explicit permit before any factory; deterministic=true alone is insufficient. Standalone EventRuntime/WorkflowRuntime APIs keep their existing checkpoint-unsupported behavior; reconstruction is available only through this new wrapper.

Quotas: at most1024 commands; complete encoded document262144 bytes; shared JSON depth32/items16384/collection1024/key128/string4096;1..1024 identity-pin entries, each path1..32 bounded identifier components. Underlying schedule/lane/window admission limits remain. Large definitions can exhaust the checkpoint header budget even within ordinary runtime limits; reject before factories. A wrapper reserves the next exact encoded command, a fixed-length digest placeholder and the greatest possible next cursor **before** mutating live state. Budget/encoding/identifier exhaustion therefore preserves the last complete checkpointable state. No overflow history buffer or partial uncheckpointable advancement is allowed. Existing standalone runtimes do not acquire this command quota.

Journal work is deliberately bounded but not optimized: append/checkpoint encoding is O(history size); execution/restore can include repeated encoding/validation and reconstruction is proportional to the admitted command prefix plus provider work. No production throughput/latency or OS resource-isolation claim is made. The quota is an explicit experimental profile limit, not automatic truncation/rolling checkpoints.

## Exact document, identities and validation

Root fields are exactly:

| Field | Meaning |
| --- | --- |
| `format`, `schema_version` | fqe.checkpoint, integer1 |
| `state_representation` | bounded-deterministic-command-replay/1 |
| `materialized_state` | false, never a native buffer import |
| `pins` | Sorted unique `{path:[identifier...],value:string}` identities; paths preserve component boundaries without ambiguous dotted concatenation |
| `journal` | Ordered `{command,outcome_id,output_cursor}` entries |
| `output_cursor` | Exact decimal string equal to final entry cursor, or0 |
| `checksum` | sha256 of canonical body excluding checksum under FQE-CHECKPOINT-CONTENT/1 |

Commands are exact discriminated objects: `ingest(stream,record)`, `watermark(stream,timestamp_ns)`, `seal(stream)`, `drive`, `retry(instance)`, `cancel(instance)`, `finish(instance)`. Market records reuse fqe.market-data/1 strict tick/closed-bar mapping, full-width numeric strings, closed OHLC/unit/scale validation and UTC timestamp semantics. Ingest preserves original source sequences; the underlying scheduler still assigns deterministic global publication sequences. Unknown fields/operations, duplicate keys/pins, bad domains/typed values, unsupported versions/representations and invalid cursors fail.

Pins bind actual core/IR/runtime source manifest and Cargo manifests/lock/toolchain, profile/outcome encoding, host run, schedule artifact/source and stream dataset IDs, lane/run/stream, workflow artifact/source/execution, registry, every compiled provider key/version/artifact/descriptor/bound-parameter hash/state schema/explicit replay capability, module/state-schema identities, temporal artifact/source/execution and instance/pending limits. Expected pins are reconstructed from already validated immutable definitions; the complete exact pin map must match. Missing/extra/changed pins fail. Parameter/entry/state-schema changes cannot be hidden by retaining a public port name. Raw source identity is intentionally stricter than semantic canonical identity.

`source_identity.rs` embeds and hashes all current core/IR/runtime implementation sources plus dependency/toolchain manifests, including its own bytes. A test requires coverage of every engine Rust source; new implementation files must join that manifest. This pins the reconstruction implementation, not a signed binary or an authentication proof of arbitrary provider/dataset bytes. Registry artifact/data IDs remain host-declared provenance; historical dataset authentication/loading remains P3. No cross-engine migration, changed-source restore, arbitrary Rust/toolchain equivalence or other-platform file durability is implied.

Outcome IDs use FQE-CHECKPOINT-OWNED-OUTCOME/1 over the versioned `owned-debug-outcomes/1` internal encoding of typed owned CommandValue/ExecutionError fields. Their BTree/Vec/Arc-inner-value representation contains no provider pointer, hash-map order, wall-clock or IO result; exact engine/toolchain pins freeze this implementation-specific digest encoding. Only hashes are stored, not a Rust object serialization. This is a strict same-engine experimental encoding, not a stable worker/client ABI. A future portable outcome codec requires its own representation/version and compatibility evidence.

Canonical/checksum identities detect corruption and divergence, not malicious forgery/authenticity. Structural/integrity/quota checks happen before factories. Expected pin/capability checks also precede factories. A restore then creates a **separate candidate**, executes each saved command privately and compares every outcome digest/cursor. A valid recomputed checksum with wrong outcomes still fails checkpoint_divergence at the journal index. Any rejection discards the candidate; it does not replace or mutate a live runtime. Restore can execute approved provider code, so untrusted implementations cannot acquire safety from a valid checksum.

## Output and failure boundaries

Successful market/lane/timer dispatch and cancel/finish closures each produce one wrapper output receipt sequence; ordinary accepted ingress/control/no-work calls do not. CommandReceipt carries command index, current output cursor, optional new output sequence and structured operation result. Rejected runtime operations are also recorded deterministically; a drive Rejected lane outcome preserves its underlying computational head/history as defined by the temporal coordinator.

Restore verifies historical receipts privately and returns only the resumed runtime; it never returns historical outputs, calls an external decision publisher or reuses already produced receipt sequences. New produced sequences continue after the saved cursor. Source logical/original sequence and window/lane identities remain unchanged. This prevents internal restore from republishing committed decisions; it does **not** establish exactly-once delivery to a client/database/SDK across a crash between returning a receipt, client acknowledgement and checkpoint publication. Durable outbox/ack reconciliation remains P4 delivery work. Legacy durably committed callbacks and trading IO are unsupported by this reconstruction profile.

Result-based rollback retains the existing trusted-provider limitations: side effects, malicious shared state, allocation/process failure, uncontained panics and a falsely asserted replay permit cannot be undone. A producer can stop at quota without losing its last valid state. Cancellation/quarantine/fairness commands are part of the prefix and are reconstructed rather than guessed from a terminal flag.

## Atomic local persistence

`checkpoint_file::prepare(path,bytes)` validates the complete bounded checkpoint first, requires a regular-file/absent target, creates a private create_new sibling temp (0600 on Unix), writes all bytes and syncs that file. It does not change the target. Dropping PreparedCheckpoint cleans the uncommitted temp. `commit()` renames in the same directory and then syncs the directory. `save()` combines these phases; `read()` accepts only bounded valid regular-file checkpoints and rejects symlink/nonregular/oversize/corrupt inputs.

A failure before rename has `PersistenceError.committed=false`; the previous target remains. A directory-sync failure after rename has committed=true: the new target was published and must not be described as rolled back. Success returns target/byte count. Filesystem/OS power-loss guarantees depend on that platform/filesystem; verified evidence is macOS ARM64, not Windows durability certification. The API assumes a trusted local checkpoint directory, not adversarial filesystem race isolation. Abrupt process exit can leave a private uncommitted sibling temp; restore reads only the explicit committed target and does not auto-promote/execute stray temp files.

## Executable evidence and remaining work

[Independent Python-encoded document](../crates/fqe-ir/tests/fixtures/checkpoint-independent.json) and [canonical bytes](../crates/fqe-ir/tests/fixtures/checkpoint-independent.canonical.json) verify a checksum/domain/canonical/full-width mapping independently of Rust; tests never regenerate them. [IR tests](../crates/fqe-ir/tests/checkpoint_contract.rs) cover strict versions/fields/corruption/cursors/quotas/programmatic command validation. [Checkpoint runtime tests](../crates/fqe-runtime/tests/checkpoint_execution.rs) split at every command for independent X-002 modules, pending queues/fairness/count windows and actual MACD/RSI/crossing/count/time histories, comparing continuation receipts and final inspected state. Blocked/retry/cancel/control-error boundaries and no historical output re-emission are explicit. Changed pins/parameters/data/schema/engine, checksum-valid wrong outcomes and command-budget exhaustion are rejected without replacing live state. [Custom-provider tests](../crates/fqe-runtime/tests/workflow_execution.rs) prove explicit capability admission before factories and opted-in stateful-extension continuation/release.

[Persistence tests](../crates/fqe-runtime/tests/checkpoint_persistence.rs) verify prepare/drop/commit, private permissions, corrupt/symlink/oversize rejection and a real child exiting after temp sync before rename; the previous committed checkpoint remains valid and later publication succeeds. This is a process-interruption test at the exact precommit boundary, not a claim to simulate physical power failure.

`cargo test --locked --offline -p fqe-runtime --test checkpoint_execution --test checkpoint_persistence` repeats the actual reconstruction/persistence acceptance. `cargo run --locked --offline -p fqe-runtime --example checkpoint` demonstrates in-memory continuation; an explicit path argument also saves the checkpoint. No new dependency, manifest, lockfile, toolchain, financial provider source or earlier golden changes are needed.

P2-05 owns user-facing bounded replay/debug traces and divergence diagnostics; internal checkpoint reconstruction alone does not deliver that task. P2-06 owns the full G-006 MACD-cross → wait3 → RSI model/gate and every wait-point restore. Native long-history state codecs, migration, external runtime state exchange, financial ledgers/backtest/simulation and actual Desk/Flutter/SDK/worker packaging are not credited by this experimental checkpoint profile.
