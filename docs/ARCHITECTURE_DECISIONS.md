# Architecture Decisions

Authority: [Charter](PROJECT_CHARTER.md) → this ADR register → scoped contracts. Accepted on 2026-11-14 for long-term direction. Accepted does **not** mean implemented. See [Status](PROJECT_STATUS.md) and [Delivery plan](DELIVERY_PLAN.md).

## ADR-001 — Rust Core

**Status:** ACCEPTED. **Decision:** Rust owns validation, execution semantics and authoritative engine state; a standalone Rust CLI remains available. **Reason:** one typed implementation for embedded and standalone consumers. **Alternatives:** putting computation in Flutter or separate evaluators per client. **Consequences:** no UI/language runtime/broker models in core; all clients share conformance fixtures. Baseline Rust workspace exists; universal engine remains P1–P3 work.

## ADR-002 — Local-First Runtime

**Status:** ACCEPTED. **Decision:** strategy execution, backtesting, optimization and debugging run locally, including user-controlled servers. Offline work has no login/account/Flutter dependency; no Finger Trader cloud customer-strategy service. **Reason:** independence, local ownership and reproducibility. **Alternatives:** hosted mandatory execution or Desktop-only runtime. **Consequences:** local resource control, datasets and packaging must be proven; external data/connectivity is an optional boundary.

## ADR-003 — Isolated Language Workers

**Status:** ACCEPTED. **Decision:** arbitrary code executes in supervised isolated language workers; deliver Python → Java → Go, with independent language acceptance. **Reason:** preserve language ecosystems without embedding their semantics into IR. **Alternatives:** embedding all runtimes or pretending arbitrary programs compile losslessly into visual graphs. **Consequences:** versioned lifecycle/state/output contracts and real failure/recovery tests; a process alone is not an OS sandbox. Transport, distribution and restriction mechanisms remain open in P5-01/P5-05.

## ADR-004 — Trading SDK Separation

**Status:** ACCEPTED. **Decision:** optional FQE adapter depends on the independent Trading SDK, never the reverse. SDK owns market/account/order/status/WebSocket APIs; FQE owns quantitative computation. **Reason:** SDK-only users must not install FQE. **Alternatives:** broker API implementations in engine or SDK depending on engine types. **Consequences:** explicit mode/permissions, no broker secrets in IR/workers, simulation cannot fall through to live. P4-04 proves the boundary without requiring live trades.

## ADR-005 — Typed Strategy IR and Event Execution

**Status:** ACCEPTED. **Decision:** a language-neutral typed graph plus event workflow and state machine expresses portable strategies. Use a universal type/parameter system, versioned node/function registries and common expressions. Indicators are registered functions, not MACD/RSI/KDJ-specific trading-condition enums. Pure computation is acyclic; cross-event feedback uses explicit State/Delay. Definitions and instance state are separate. **Reason:** visual and declarative clients share semantics without special-case strategy logic. **Alternatives:** indicator-specific enums, untyped graphs, mutable definitions. **Consequences:** compiler validation, graph/type errors, warm-up and state boundaries need executable tests. The current price-only Rust IR is experimental baseline, not fulfillment of this ADR.

## ADR-006 — Vertical Slice Delivery

**Status:** ACCEPTED. **Decision:** deliver executable model-to-result slices within P1–P6, with dependency gates and independent evidence. **Reason:** avoid empty interface scaffolding being counted as capability. **Alternatives:** completing all abstractions first or expanding the demo into all products at once. **Consequences:** no stage completion from documents alone; each task has acceptance/tests, committed evidence and handoff. This governance work does not complete P1.

## ADR-007 — Local Simulation

**Status:** ACCEPTED. **Decision:** FQE owns local virtual accounts, fills, cash/positions, fees/slippage, leverage/margin and versioned broker simulation profiles. No backend simulated account is required. **Reason:** complete independent local research loop. **Alternatives:** server-owned paper accounts or treating signals as fills. **Consequences:** financial numeric/rounding policy and independently calculated ledger tests gate P3. Supported profiles must be explicit; no realism or live-equivalence promise.

## ADR-008 — Versioned Plugin Extensibility

**Status:** ACCEPTED. **Decision:** versioned plugin manifests/registry, dependencies, capability negotiation, permission model and compatible model packaging support third-party indicators/functions/modules and future marketplace consumers. **Reason:** extensibility without core-specific forks. **Alternatives:** unversioned dynamic loading or marketplace-driven engine dependency. **Consequences:** proven load/execute/unload, resource enforcement and fault isolation precede release claims. Native ABI, WASM or out-of-process execution is not selected; P6-01/P6-02 evaluate mechanisms.

## ADR-009 — Versioned Public Contracts

**Status:** ACCEPTED. **Decision:** IR, protocol, registry entries, modules, worker, snapshot and plugin contracts are versioned independently. Protocol Buffers is the first candidate to evaluate, not a proven codec/transport. **Reason:** cross-language exactness and deliberate compatibility handling. **Alternatives:** exposing internal Rust structs as public ABI or inferring compatibility from engine package versions. **Consequences:** presence, exact integers, limits, unknown required capabilities and malformed payload tests. Existing `.proto` is only an experimental draft; P1-03 evaluates encoding and P4-01/P5-01 evaluate transport.

## ADR-010 — One Engine, Optional Desktop Boundary

**Status:** ACCEPTED. **Decision:** evaluate FFI and IPC for Desktop/external consumers; choose from measured correctness, lifecycle, safety, overhead and packaging evidence. CLI and Desktop use identical engine semantics. **Reason:** embeddability without Flutter dependence. **Alternatives:** a second evaluator in Dart or premature transport commitment. **Consequences:** P1-10 provides a minimal external-process smoke test; stable FFI/IPC selection and actual Desktop parity wait for P4-01/P4-05. Current `unsafe_code = forbid` remains intact; any native-boundary exception needs a separately reviewed scope.

## ADR-011 — Desk Embedded Delivery and Migration

**Status:** ACCEPTED on 2026-11-14, owner-directed product clarification. **Decision:** the existing `finger_desk` application is the primary integration target. Deliver the first backtest/local simulation loop inside its supported app package; preserve standalone/offline FQE. Desk is optional to engine users, while actual Desk delivery is required for project completion. FQE owns computation/financial state for FQE runs; Desk owns presentation, saved drafts and client orchestration. Existing Dart/Python paths and old records require explicit versioned migration/compatibility, with one authoritative backend per run. **Reason:** an independent engine must ultimately power the existing Desk quant product, whose working tree already contains local Python execution, financial computation and durable records. **Alternatives:** a separate demo Desktop, postponing consumer semantics until release, or leaving two authoritative ledgers. **Consequences:** [Desk integration](DESK_INTEGRATION_PLAN.md) binds existing P1/P3/P4/P5/P6 acceptance to real consumer contracts, paired candidates and installed native evidence. First scope is historical backtest/local simulation, as confirmed by the owner; live execution is separately accepted. P4 proves portable-model integration, P5 proves Python integration and P6 repeats final bundled acceptance. FFI vs IPC remains open under ADR-010; this decision does not select or implement a mechanism. Prior governance's initialization-only exclusion of Desk edits remains historical, not a permanent exclusion of integration delivery.

## ADR-012 — Open Language and Computation Extensions

**Status:** ACCEPTED on 2026-11-14, owner-directed extensibility clarification. **Scope refinement:** extends the initial language list and Python-only Desk milestone in ADR-003/ADR-011; their isolation, migration and offline boundaries remain in force. **Decision:** support an open adapter/provider ecosystem within versioned types/events/capabilities. Separate engine-client, whole-strategy-runner and callable-computation-provider roles. Shared descriptors drive generic compiler invocation and Desk discovery/parameters/ports; indicators and predicates can be implemented in any conforming adapter language. Python → Java → Go and initial indicators are reference implementations, not a closed catalog. New conforming entries need no per-name core/IR/UI change; genuinely new host capabilities require versioned evolution. **Reason:** financial formulas and strategy languages continue to grow, so reference examples alone cannot prove extensibility. **Alternatives:** a fixed language enum, growing per-indicator condition enums, or separate language-specific financial engines. **Consequences:** [Extensibility contract](EXTENSIBILITY_CONTRACT.md) is normative; P1 proves unknown-name provider injection before external loaders; P2 proves portable extension state; P4 provides descriptor-driven Desk; P5 delivers onboarding tools and real fourth-language child task P5-05.01; P6 delivers Java-indicator/Go-predicate graph child task P6-03.01 and final native acceptance. Parent gates depend on their children, never the reverse. Java/Go do not require Python at runtime. Arbitrary source translation, identical arbitrary-language results and support for unimplemented/unavailable runtimes are not promised. Transport/execution/isolation choices remain evidence-gated under existing ADRs.

## ADR-013 — Checked Decimal and Bounded Parameter Subset

**Status:** ACCEPTED on 2026-11-14 for the P1-02 slice; experimental API. **Decision:** retain the legacy positive-u64 demo while adding checked signed i128 decimal coefficients with explicit scale 0–18, equal-scale arithmetic and explicit Exact/TowardZero/HalfEven rounding. Implement validated scalar/unit descriptors, explicit readiness and immutable parameter schemas/bindings; reject unsupported shapes/types and implicit conversions. **Reason:** executable probes confirm exact decimal inputs and large integers, float precision loss, integer division truncation, and the need for explicit finite-range/rounding behavior. **Alternatives:** positive ticks only; binary64 scalar values; bounded/unbounded rational arithmetic; new third-party decimal/BigInt dependencies. **Consequences:** [Type/parameter contract](TYPE_PARAMETER_CONTRACT.md) records numeric evaluation, coefficient/intermediate-overflow limits, supported APIs and public-API tests. No dependency or legacy API behavior changes. A representable result may still be rejected when a checked intermediate overflows. This does not decide indicator working precision/error tolerances (P1-06), ledger rounding (P3-01), codecs, provider execution or arbitrary numeric type support. These remain separately evidence-gated.

## ADR-014 — Bounded JSON Models and Versioned Content Identity

**Status:** ACCEPTED on 2026-11-14 for experimental P1-03 import. **Decision:** strict bounded JSON using reviewed Serde/serde_json, explicit full-width numeric strings, immutable IR2 declarations, separate raw-source SHA-256 and FQE canonicalization-v1 SHA-256 identities using reviewed sha2 software implementation. Bindings pin exact content. Unknown fields, versions, duplicate keys, unsupported future fields and external dependencies fail closed. **Reason/evidence:** real tracked file/canonical bytes independently calculated with Python json/hashlib, exact integer/decimal/unit tests, duplicate/depth/item/byte/reader failures and binding matrix pass; see [Model loading](MODEL_LOADING.md). **Alternatives:** hand-written parser/cryptography adds avoidable risk; custom binary/TLV increases interoperability burden; the draft Protobuf cannot express the universal model and would require separately reviewed schema/generator work. **Consequences:** [Dependency review](P1_03_DEPENDENCY_REVIEW.md) records owner authorization, all 21 resolved archives/metadata/build scripts and public OSV results. JSON model format selection does not select Desktop/worker transport or implement the draft Protobuf codec. Canonicalization is not RFC 8785 or signature/trust verification. Model schema 1/IR2 is explicitly separate from legacy IR1. Full registry/signature/cycle validation, reusable module expansion and execution remain P1-04/P1-07/P1-08.

## ADR-015 — Frozen Pure Scalar Provider Registry

**Status:** ACCEPTED on 2026-11-14 for experimental P1-04. **Decision:** one shared immutable callable descriptor and exact-pinned frozen registry for built-in and independently defined reviewed in-process providers; typed named scalar multi-input/output signatures, parameter schema/relationship validation and checked eager readiness/output handling. Descriptor and registry canonical identities are independent of registration order. Model-node preparation retains model/node plus registry/descriptor identity. **Reason/evidence:** two loaded unknown-name function/predicate compositions, independent descriptor JSON/SHA fixture and version/artifact/type/arity/readiness/resource/panic negatives; [Provider registry](PROVIDER_REGISTRY.md) owns exact APIs and limits. **Alternatives:** name-specific enums/dispatch, mutable live registry upgrades or treating a strategy-runner callback as a callable function service. **Consequences:** no additional dependencies. Pure reviewed Rust traits are not a stable foreign ABI, isolation mechanism, complete graph compiler or scheduler. Indicator/history/state support, lifecycle/event commit, external provider mapping/execution and client discovery remain separately versioned later-task acceptance. Unwinding panic conversion cannot police side effects, loops or aborts. Source-artifact pins are declared by reviewed registration code, not cryptographic attestation of arbitrary objects.

## ADR-016 — Typed Expressions with Eager Crossing Subscriptions

**Status:** ACCEPTED on 2026-11-14 for experimental P1-05. **Decision:** bounded immutable typed in-memory expression plans with generic P1-04 calls; exact checked arithmetic and explicit dimensional/rounding restrictions; documented five-state left-to-right Boolean semantics. Evaluate all crossing subscriptions once in stable dependency order before roots, independently of guards/shared references. Stage history and commit only after every root succeeds; accepted Missing/Warmup resets a prior pair, numeric errors leave it intact. **Reason/evidence:** independent truth tables/arithmetic/cross edge fixtures, false guards/operand reordering/shared-call count, dependency cycles, retry/isolation and failed evaluation rollback tests. [Expression contract](EXPRESSION_CONTRACT.md) owns exact rules and resource ceilings. **Alternatives:** lazy crossing updates inside Boolean short-circuit, implicit zero/false for missing data, in-place history writes and arbitrary unit-preserving multiplication. **Consequences:** no new dependencies; no external AST format/graph compiler, indicator precision, market scheduling or snapshot support. Decimal domain products/divisions and mixed units fail until explicit dimensional functions/policies exist. Trusted pure provider side effects and process failures are outside local rollback. This does not close P1-06/P1-07/P1-08 or P2 gates.

## ADR-017 — Bounded Decimal Indicators and Owned Incremental Providers

**Status:** ACCEPTED on 2026-11-14 for experimental P1-06. **Decision:** registered version-1 SMA/EMA/MACD/RSI use checked i128 work18/output12, HalfEven at declared formula boundaries, mean seeds/Wilder/flat50, bounded periods/inputs and an explicit RSI conditioning guard. A negotiated incremental-scalar/1 descriptor profile uses shared frozen registration with fresh per-instance provider state, deep staged copies and validated single-node commit; stateful entries cannot enter pure calls. Preserve descriptor schema 1 and exact prior pure canonical bytes; actual state declarations enter identity. **Reason/evidence:** [independent rational evaluation](P1_06_NUMERIC_EVALUATION.md), nine tracked datasets/563 samples, warm-up/seed/large-value/tie/threshold and G-007 crossing checks; provider failure/panic/invalid-output rollback and isolated unknown-name stateful tests. [Indicator contract](INDICATOR_CONTRACT.md) owns all limits, error bounds and APIs. **Alternatives:** work12 loses guard precision; binary64 loses output quanta at supported large magnitudes; new arbitrary-precision dependencies increase scope; globally shared mutable indicator objects and repeated lazy pure calls break history ownership. **Consequences:** no new dependencies, unchanged legacy IR1; RSI rejects tiny nonzero mean movement (<1e-6 input units), and rounded comparisons can differ from ideal rational boundaries. Not a ledger policy, external ABI, snapshot codec, full graph compiler or atomic multi-node event runtime. P1-07/P1-08 and P1-11 retain those integration/gate requirements; P3-01 owns financial rounding. Reviewed Rust traits cannot enforce clone correctness, isolation or quotas.

## ADR-018 — Explicit Typed Graph Artifacts and Bounded Pure Module Compilation

**Status:** ACCEPTED on 2026-11-14 for experimental P1-07. **Decision:** preserve fqe.model/1 canonical syntax and add a separate fqe.graph/1 artifact for typed public inputs and inline pure modules. Compile both through exact frozen provider descriptors into bounded, stable topological plans with scoped path vectors, immutable bound parameters, module/registry/model/descriptor identities and original syntax/call-site source maps. Deferred incremental preparation validates without creating state. Optional pure plans lower to the existing bounded P1-05 AST; stateful entries cannot enter it. **Reason/evidence:** real X-001 original and nested/reused rule compositions execute with independent arithmetic decisions; independent graph canonical bytes/SHA, declaration reorder/identity changes, recursion/cycle/parameter/type/expansion limits and zero factory creation tests. [Graph compiler contract](GRAPH_COMPILER.md) owns syntax, limits, identity and supported execution boundary. **Alternatives:** silently enabling nonempty modules in old schema; ID-specific compiler branches; flattening scoped IDs into ambiguous slash strings; creating indicator state during compilation; unbounded AST/module expansion. **Consequences:** no new dependencies; inline module closure is pinned by the root artifact, not an external package loader. Pure projection may repeat calls and fail its smaller AST budget for a valid DAG. Standalone operator/cross AST serialization and compiled market-event subscriptions/atomicity remain P1-08 integration requirements before P1-09/P1-11; arbitrary workflows/state/delay remain P2. Trusted validators execute during preparation and cannot be sandboxed by these Rust interfaces. No Desk or financial ledger acceptance is implied.

## ADR-019 — Explicit Event Profile and Whole-event State Commit

Stage every incremental node in stable dependency order, then all crossing subscriptions and lazy Boolean roots; publish all state/cursors/signals only after success. CLI/data codecs and the P1 gate remain downstream tasks.

## ADR-022 — Atomic Host-Owned Scalar Workflow Modules

**Status:** ACCEPTED on 2026-11-14 for experimental P2-01 after full verification. **Decision:** add a separate bounded fqe.workflow/1 library profile over the existing compiled event plan, reusing typed expression/parameter/numeric validation. Reject conflicting control targets/writes and unready state writes. Inspection is typed and explicitly non-restorable; full provider/schema/cursor checkpoint and split-run acceptance remain P2-04. Multi-market scheduler, timers, temporal G-006, worker transport and Desk packaging remain later tasks. No dependency or lockfile change.

## ADR-023 — Inclusive Watermarks and Sequential As-Of Market Alignment

Candidate alignment contains only the current/published records. P1 APIs/fixtures/provider sources and dependencies remain unchanged except shared parser/identifier visibility.

## ADR-024 — Typed Latching Windows and Bounded Workflow Lanes

**Status:** ACCEPTED on 2026-11-14 for experimental P2-03 after full verification. **Decision:** bind strict fqe.temporal-rules/1 Boolean sources to exact workflow execution identity; own count/event-time latching windows in the Rust host. Exclude arming event, include expiry event, ignore active/expiry re-arms and fire event-time expiry after watermark-complete market phases. A bounded coordinator atomically enqueues per-stream fanout, stages workflow/provider/crossing/temporal computation together and fairly dispatches independent lanes. Failed lanes quarantine their unchanged head for explicit retry/cancel; incomplete count waits are reported at EOF. **Reason/evidence:** generic independent bar2→bar5 boundary cases, absent expiry bar, timer ties/watermark stalls, repeated shared-model isolated runs, atomic fanout backpressure and real incremental-provider/crossing rollback on temporal overflow. **Alternatives:** counting all input ticks, wall-clock timers, evaluating expiry before its final predicate sample, auto-rearming on expiry, globally blocking every lane on one error, or mutating a workflow before validating its candidate temporal effects. **Consequences:** [Temporal scheduler](TEMPORAL_SCHEDULER.md) owns exact profile/capacity/phase/lifecycle and source identities. This is synchronous bounded coordination, not preemption/sandboxing, durable output delivery, a graph cross-domain join or complete G-006/restore gate. P2-04/P2-05/P2-06 retain snapshot/replay/full temporal acceptance; dependencies/financial arithmetic/provider source pins remain unchanged.
