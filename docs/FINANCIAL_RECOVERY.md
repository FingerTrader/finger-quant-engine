# Complete bounded financial continuation

Experimental P3-07 `financial_checkpoint::FinancialSession` composes the [Backtesting](BACKTESTING.md) history/strategy/policy/financial pipeline. [P3 acceptance](P3_ACCEPTANCE.md) owns full gate evidence; [Project status](PROJECT_STATUS.md) owns closure. This is a separate `fqe.financial-checkpoint/1` representation; the prior P2 [checkpoint contract](CHECKPOINT_RESTORE.md) and codec remain unchanged.

## Complete logical state and explicit capability

A native immutable PreparedBacktest freezes compiled Event/Workflow, exact financial input manifest, selected history and ordered policies/configuration. FinancialSession requires RunControl Complete and explicit deterministic reconstruction permission on every compiled graph provider, checked before any provider factory runs. An independent registry defaults to denied; the existing reviewed reference catalog explicitly permits its deterministic implementations. The permission is a trusted purity/determinism assertion, not isolation for hostile code or authority for network/IO side effects.

The session exposes a Paused prefix, source cursor, advance, checkpoint, restore and full finish. Each prefix reconstructs all earlier bars in order through the actual Event/Workflow evaluator, policies, broker and ledger, without Finish. Thus pending reservations, FIFO/partial fills, strategy indicator/crossing/module/delay buffers, fees/rounding, debt/repayments, margin state/forced orders, observations/decisions/equity and source/output cursors are determined by the complete pinned recipe. Opaque provider buffers are rebuilt; they are not replaced by guessed counters, serialized Rust objects or broker-only summaries. Registry implementations and the exact prepared artifacts/data must be supplied by the host; checkpoint bytes do not download/embed source data or native function pointers.

Every advance builds a separate prefix candidate from the start. It verifies the previous committed observations, decisions, equity points, broker receipts, fills and full journal are exact prefixes of the new candidate before replacing current. Failure leaves the original complete prefix unchanged. Restore reconstructs a separate candidate and verifies the entire canonical paused-prefix result ID, which includes all those outcomes plus current orders/holds/account/risk/metrics and input pins. This matches ADR-025's bounded logical reconstruction principle. It is not a native compact snapshot or constant-time continuation. At most256 bars, potentially quadratic work across repeated advance, with no CPU/isolation/production-latency guarantee. A false provider permission can violate hidden-state determinism; observed divergence rejects when detected.

## Phase and output semantics

New sessions start Paused at source cursor0 with the opening ledger and unconsumed history. advance consumes exactly one next bar and returns only its newly committed observation. The current getter is a read-only historical prefix, not a stream of newly emitted outputs. Restore returns no historical observations as new receipts; the next advance starts after the saved cursor. Client acknowledgement/exactly-once delivery is not modeled here; P4 owns external cursors/protocol semantics.

A paused prefix never calls strategy or broker Finish: holds/partial orders/debt/liquidation remain live. `BacktestTerminal::Paused` and JSON terminal paused make this explicit. finish is allowed only once every selected source bar is consumed; it applies the original Finish/release/repay policy, validates previous prefix continuity and produces the exact same completed report bytes as uninterrupted PreparedBacktest.run. An early or repeated finish, advance beyond end, or checkpoint after finish rejects without mutation. Stop/cancel financial reports remain the separate existing bounded batch RunControl/AtomicBool API; persisted mid-session cancel controls and optimizer resume are not implemented.

## Envelope and compatibility

Checkpoint payload fields: format `fqe.financial-checkpoint`, integer schema_version1, representation `bounded-financial-prefix-reconstruction/1`, manifest_id, engine_id, canonical decimal string source_bars0..256, prefix_id. content_id = SHA256(`FQE-FINANCIAL-CHECKPOINT/1` + newline + sorted compact payload bytes excluding content_id). prefix_id is the existing `FQE-BACKTEST-RESULT/1` domain hash of the complete actual paused result, not a cursor-only checksum. Root JSON requires exactly the eight known fields, strict existing duplicate/number/depth/item/262144-byte decoding, canonical ContentIds and source count. Formatting whitespace may differ without changing semantic envelope integrity.

Restore validates shape/version/representation/integrity, current engine and exact prepared financial manifest ID, cursor within selected range and provider permissions before instantiating provider state. Financial manifest pins engine/artifact/actual parameters/provider registry/data/revision/range/warmup/instrument/steps/account/model/cost/risk/policies/seed. Any change fails compatibility rather than migrating or silently changing semantics. A forged but well-formed/checksummed prefix ID still fails after actual reconstruction. Hashes establish identity/integrity, not authenticated market data or an adversarial signature.

## Private atomic files

`checkpoint_file::prepare_financial(...).commit()` and read_financial validate this envelope separately and reuse the existing publication implementation: bounded regular-file/symlink checks, same-directory create_new temp at0600 on Unix, complete write/file-sync, atomic rename and parent-directory sync. A post-rename directory-sync failure explicitly has committed=true; dropping an uncommitted prepared write removes its temp. An actual process exit before rename leaves the old committed target, possibly an orphan private temp. Caller-owned local trusted directories are required; this is not a hostile-directory race-proof filesystem sandbox. The old P2 prepare/read retain their original SnapshotDocument validation and cannot accept a financial envelope.

## Executed acceptance

Seven integration tests cover eight combinations of Event/Workflow × cash/margin × full/partial volume, every source split0..7, exact resumed/uninterrupted final JSON and no duplicate newly returned observation; pending cash/long holds, partially filled orders, principal debt and failed next-bar atomicity; default-deny, malformed/duplicate/truncated/unknown/version/cursor/engine/manifest/prefix-integrity checks; premature/end lifecycle; private atomic publication/symlink rejection and actual child exit73 before rename. A separate three-bar real history/explicit policy/margin fixture restores at every close, including debt1000 and a pending protected forced sale at the close-maintenance breach, then final Liquidated/cash100/net−900. Automatic BuyIfFlat explicitly records risk_disabled after breach instead of aborting an otherwise valid financial report by resubmitting forbidden risk.

`cargo run --locked --offline -p fqe-runtime --example financial_checkpoint` saves after bar5 with a real pending buy reservation, drops the parent session, launches a fresh native child binary, reads/validates/restores from disk, advances bars6/7 and finishes. Parent compares the child's complete report bytes to uninterrupted execution: final97/fees1. This is actual cross-process financial continuation, separately from the injected pre-rename crash. No new dependencies/toolchain/lock/provider/golden changes, installers/private uploads or Desk execution.
